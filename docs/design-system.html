Design System · v3

Money that moves as fast as a message.

Seti turns a WhatsApp thread into a settlement rail. This system keeps every surface, from a quote card to a status update, speaking with the same calm, exact voice.

01 — Principles

What this brand has to be true to

These are not values off a poster. They are constraints that came directly out of building the product. Every visual and verbal choice should trace back to one of these.

State the truth, not the hope

A confirmation on one chain is not a payout. We show progress as progress and never round a pending transfer up to "done."

One thread, not one app

The whole product fits inside a conversation. Nothing in this system should ask someone to leave WhatsApp to understand what happened to their money.

Borderless by default

A quote works the same whether the recipient is across town or across a border. The design does not add ceremony to something that should feel ordinary.

Show your work

Every transfer carries a reference, a hash, a receipt. Data that proves what happened is never hidden behind a friendlier-sounding message.

02 — Voice

Concise, transactional, reassuring under uncertainty

People are moving real money inside a chat window. Clarity beats friendliness, but clarity delivered coldly reads as a system that does not care whether the money arrived.

Avoid
"Your transaction is being processed by our sophisticated verification pipeline."
Instead
"Your swap and transfer both confirmed. We are waiting on the final payout now."
Avoid
"ERR_IDEMPOTENCY_MISMATCH: duplicate key rejected."
Instead
"That confirmation code has already been used. No charge was made twice."
03 — Logo

The wordmark, with a wireframe globe as a secondary mark

The globe is an open wireframe sphere, never a solid icon. It should read as structure you can see through, echoing the ledger underneath every transfer. Minimum clear space around the lockup equals the height of the globe mark itself.

09 — Ground rules

Fast to check, hard to get wrong

Do

  • Show a transaction ID or hash any time money moves.
  • Say "confirmed" only once the backend has confirmed it.
  • Use the four status colours consistently — never invent a fifth.
  • Keep the globe mark as open wireframe, never filled.

Don't

  • Show an internal error code or state name to a user.
  • Use a gradient, heavy shadow, or bright hero background.
  • Round an in-progress transfer up to "complete."
  • Use emoji in system icons, headings, or alt text.
